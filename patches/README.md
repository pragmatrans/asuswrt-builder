# Патчі до дерева Asuswrt-Merlin для RT-BE92U

Наш шар змін поверх стоку. Накладаються **останніми** в конвеєрі — після `git clone`, cherry-pick
(`commit_manifest`) і підстановки prebuilt-блобів (`blob_commit`). Префікси в патчах — `a/release/...`,
тобто застосовуються з кореня репозиторію.

Принцип: **кожна зміна має причину, ціну й спосіб відкату.** Нижче — по кожному патчу. Хто читає це
через рік, має зрозуміти не лише «що змінено», а й «чому саме так» і «що ми цим втратили».

| патч | одним рядком | крихкість до нового дерева |
|---|---|---|
| `jffs-to-tmp.patch` | логи з NAND у tmpfs: не зношувати флеш | висока (7 файлів, гарячі місця) |
| `regulatory-db-lib-firmware.patch` | підписана база регуляторних доменів потрапляє туди, де її шукає ядро | низька |
| `busybox-httpd.patch` | свій маленький HTTP-сервер для логів по LAN | низька |
| `optional/no-asd-ark.patch` | без телеметрії й без Ark-движка (не за замовчуванням) | висока (залежить від ARK) |

---

## 1. `jffs-to-tmp.patch` — логи в `/tmp`, а не в `/jffs`

**Що робить.** Прибирає `PSISTLOG=y` з профілю `HND-96765_BASE` і переносить у `/tmp` шляхи решти
логів, зашитих у джерелах: `httpd/common.h` (3 `#define`), `httpd/web.c` (читання журналу входів),
`rc/common.c` (3 шляхи архівів feedback), `rc/watchdog.c` (4 сайти `cfg_dbg.log`), `aaews/common.h`,
`rom/webs_scripts/ssl_webs_download.sh`.

**Навіщо.** `PSISTLOG=y` — це не «налаштування», а `RTCONFIG_PSISTLOG`, від якого `syslogd`
отримує `-O /jffs/syslog.log`. Тобто головний письменник у NAND — сам системний лог, з ротацією
256 КБ × 2. У пристрої, який працює роками, це найшвидший спосіб зносити флеш і заодно забрати її
в того, для чого вона є (`/jffs/configs`, скрипти, ключі). У `/tmp` (tmpfs) лог живе в RAM,
коштує нуль записів у NAND і зникає при ребуті — для діагностики «тут і зараз» це нормальна ціна.

**Як саме.** Джерельний `#else` у `get_logfile_path()`/`get_syslog_fname()` уже повертає `/tmp`,
тому основна частина — **нуль правок C**: досить зняти прапорець. Решта — точкові заміни рядків
у місцях, де прапорця немає взагалі (`debuglog_*.tgz`, `cfg_dbg.log`, `security_recored.log`).

**Компроміси.** Логи не переживають ребут — це і є мета. Журнал входів `security_recored.log`
роз'їдеться на два місця: джерельний `web.c` писатиме в `/tmp`, а prebuilt `web_hook.o` — далі
в `/jffs`, бо шлях зашитий у бінарник. Частина логів ASD/AiProtection (`asd.log`, `amas_*`,
`s46.log`) лишається в `/jffs` з тієї ж причини — їх лікує тільки бінарний патч, якого ми свідомо
не робимо.

**Перевірка на пристрої.** `ls /jffs` — немає `syslog.log`, `syslog.log-1`; `syslogd` у `ps` із
`-O /tmp/syslog.log`; системний лог у WebUI все одно показується (UI читає той самий файл).

**Відкат.** `git checkout --` по семи файлах, або просто не застосовувати патч.

**Повний розбір** — `jffs-to-tmp.md`: таблиця «файл:рядок → що пише → чим керується», мертвий для
цієї моделі код, перелік prebuild-бінарників із зашитими шляхами, оцінка кожного ризику.

## 2. `regulatory-db-lib-firmware.patch` — база регуляторних доменів у `/lib/firmware`

**Що робить.** Додає в `rom/Makefile` (ціль `install`) копіювання `regulatory.db` і підпису
`regulatory.db.p7s` у `$(INSTALLDIR)/lib/firmware/`.

**Навіщо.** `regulatory.db` — підписана база регіональних обмежень, яку `cfg80211` вантажить
**через firmware loader**, тобто з `/lib/firmware`. У дереві merlin файл лежить у `rom/lib/firmware`,
а каталог `rom/` пакується в `/rom` — це не шлях пошуку фірмваря, і ядро цей файл не бачить.
Без бази драйвер живе на вбудованих «світових» обмеженнях: частина каналів і ширин недоступна,
поведінка відрізняється від стоку.

**Як саме.** Крок умовний (`if [ -f ... ]`): якщо файлу немає — збірка не падає, просто нічого не
копіюється. Джерело — `rom/lib/firmware`, куди його викладає крок збірки з пакета `wireless-regdb`.

**Компроміси.** Немає: файл підписаний, розмір — одиниці кілобайт, впливає лише на коректність
регуляторних правил. Єдиний ризик — тихий: якщо в новому дереві перепишуть `rom/Makefile`, хюнк
може застосуватись, але копіювати нічого буде. Тому перевірка обов'язкова.

**Перевірка.** `ls -l /lib/firmware/regulatory.db*` — файл і `.p7s` на місці; `dmesg | grep -i regdb`
без «failed to load regulatory.db»; `iw reg get` показує код країни, а не `00`.

**Відкат.** Прибрати хюнк із `rom/Makefile`.

## 3. `busybox-httpd.patch` — власний HTTP-сервер для логів

**Що робить.** Вмикає аплет `CONFIG_HTTPD` у `busybox/config_base` (Асус збирає busybox без нього).

**Навіщо.** У прошивці команда `httpd` — це закритий веб-сервер Асуса (той, що віддає WebUI):
він не вміє `-p`/`-h`, не запускається другим екземпляром на іншому порту і не віддає довільний
каталог. Коли треба швидко подивитися логи або віддати файл по LAN, потрібен окремий маленький
сервер — busybox-аплет і є такий: десятки кілобайт у вже наявному бінарнику, без нових залежностей.

**Як саме.** Один рядок конфігу.

**Компроміси.** Аплет **без автентифікації** (`FEATURE_HTTPD_BASIC_AUTH` не ввімкнено) — запускати
вручну, тільки в LAN, і гасити після роботи. Це діагностичний інструмент, а не сервіс. Другий
нюанс: голий `httpd` на `PATH` — Асусів бінарник, тому busybox-аплет викликається як
`busybox httpd`.

**Перевірка.** `busybox --list | grep httpd` показує аплет; `busybox httpd -p 8080 -h /tmp` →
`curl -I http://<lan-ip>:8080/` віддає 200.

**Відкат.** Прибрати рядок — аплет зникне з бінарника.

## 4. `optional/no-asd-ark.patch` — без телеметрії й без Ark (не за замовчуванням)

**Що робить.**
- `GTBOOSTER=y` → `n`: Ark-движок (Adaptive QoS / Game Booster) не збирається;
- `asd-install` стає порожньою ціллю: демон `asd` (телеметрія/аналітика Асуса) у образ не потрапляє;
- `shared/Makefile`: `ark_utils.o` лишається в лінку **завжди**, бо `misc.c`/`rc`/`httpd` кличуть
  `ark_*`-функції без `#ifdef`;
- `rc/Makefile`: при `GTBOOSTER=n` у лінк додається `ark_stub.o`;
- новий файл `rc/ark_stub.c`: `int IS_ARK_IAM(void) { return 0; }`;
- `router/Makefile`: `libasc` стає залежністю цілі `rc` (`$(if $(RTCONFIG_TPVPN),libasc)`).

**Навіщо.** Пристрій працює точкою доступу: QoS-движок, Game Booster і хмарна аналітика йому не
потрібні, а `asd` — демон, який постійно щось збирає й кудись шле. Менше рухомих частин — менше
поверхні атаки, менше памʼяті, менше фонових записів.

**Чому це не «просто вимкнути прапорець».** `ASD=y` лишається, бо від нього залежить
`RTCONFIG_LIBASC`: `rc` лінкується через `-lasc`, і без `libasc.so` падає `libcreduction`
(«Missing 32-bit libraries: libasc.so»). Тому ми не ламаємо збірку `asd`, а **не встановлюємо**
його бінарник у образ. Далі: prebuilt `amas_lib.o` (закритий, лінкується завжди) кличе
`IS_ARK_IAM()`, а єдине визначення цього символу — в `ark.o`, що збирається лише при
`GTBOOSTER=y`; без заглушки лінк падає на `undefined reference to 'IS_ARK_IAM'`. І `ark_utils.o`
мусить лишитись у лінку незалежно від прапорця, бо його функції кличуть `misc.c`/`rc`/`httpd`
без `#ifdef`.

**Компроміси.** Немає Adaptive QoS і Game Booster (для AP не потрібні), немає AiProtection-аналітики
(це і є мета), сторінки WebUI, що показують Ark/QoS, будуть порожніми або зникнуть. Патч крихкий:
тримається на внутрішній структурі ARK у конкретному SDK — при переході на новий SDK перевіряти
першим.

**Перевірка.** `ls /asd/usr/bin/asd` — немає; `ps | grep -E 'ark|asd'` — порожньо; WebUI
відкривається, пристрій нормально стартує як AP.

**Відкат.** Не вмикати патч (він у `optional/`), або повернути `GTBOOSTER=y` і прибрати
`ark_stub.o` з `OBJS`.

---

## Порядок і сумісність

Три основні патчі незалежні й застосовуються в будь-якому порядку. `no-asd-ark` файлово не
конфліктує з `jffs-to-tmp`, але логічно пов'язаний: після вирізання `asd` його `/jffs/asd.log`
зникає сам — тобто один із prebuild-«хвостів», описаних у `jffs-to-tmp.md`, закривається без
бінарного патчу.
